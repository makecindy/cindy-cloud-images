# Cindy 云主机镜像与交付验收

用户从自己的 Cindy 账号打开新主机后，应能立即发任务。选了桌面版的用户还应该能直接打开远程桌面、点击链接、在浏览器中工作，以及查看任务下载的文件。

## 随镜像准备的能力

| 能力 | 桌面镜像 | Host 镜像 |
| --- | --- | --- |
| 自动登录和开机启动 | XFCE 启动 Cindy，交付时绑定购买者的账号 | systemd 用户服务先完成注册，再启动 Host |
| 操作电脑 | 独立的 X11 会话，包含 XTest 输入、剪贴板工具、AT-SPI 和用户 D-Bus | 终端和后台任务 |
| 浏览器 | Chrome Stable 预装并处理网页链接，Firefox 可选。Cindy 可发现本机 Chrome | 由具体任务安装所需浏览器 |
| 文件与开发 | Thunar、Mousepad、PDF 查看器、压缩包管理、Git、ripgrep、rsync、curl、jq | 随 Host 制品提供 Node 运行时，项目工具按任务准备 |
| 语言与显示 | 交付参数决定初始语言、时区和分辨率。预装中文字体和 emoji 字体 | 随 Ubuntu 基础环境 |
| Cindy 更新 | 首次开机装上最新正式版；之后系统包由 Cindy 自己更新，无人值守时空闲安装，见下文 | 固定为镜像里的版本 |

桌面版 Cindy 是官方的系统 `.deb`，沿用它自带的 setuid 沙箱。Cindy 更新时通过 `pkexec` 替换系统包；桌面用户本来就有免密 sudo，所以镜像装上 `pkexec`，并用 `/etc/polkit-1/rules.d/49-cindy-cloud-desktop-update.rules` 让桌面用户的 `pkexec` 不再弹出没人能输的密码框，不多给权限。云主机平时没人点「重启以更新」，首次开机的 `activate` 会在 Cindy 启动前为桌面用户写入 `auto-update-settings.json`，打开空闲时自动安装；文件已存在时不改，用户关掉后保持关闭。国内版写在 `~/.config/Cindy`，国际版写在 `~/.config/CindyGlobal`。

镜像里的 Cindy 停在制镜时的版本。为了不让新开的机器先打开旧版、用不了多久又因更新重启，每台机器第一次开机时由 `cindy-cloud-desktop-update.service` 先装好最新正式版，桌面会话等它结束再启动 Cindy，最多等 20 分钟。它按镜像里 Cindy 的区域读取国内或国际的更新清单，只接受与已装包同名、同架构、版本号与清单一致的 `.deb`，并核对清单给出的 SHA-256。下载停滞、校验不符或开机 10 分钟内没下载完时保留镜像里的版本，之后交给 Cindy 自己更新。安装只在开机 10 分钟内开始，不会被时限打断；安装失败时 dpkg 会放回旧文件，停在配置阶段的会补完配置。完成后写入 `/var/lib/cindy-cloud-desktop/update.done`，之后开机不再运行；封存镜像时会删除这个标记，原地重装后的新系统盘也会重新检查。

Chrome 从 Google 的签名 APT 源安装，信任只用于该源。制镜时会记录浏览器初装版本。用户可修改自己的默认浏览器。Cindy 管理的浏览器配置和用户日常 Chrome 配置都在来宾内首次创建。

## 权限由谁授予

- **系统会话**。X11 屏幕、输入、剪贴板和无障碍接口准备在当前桌面用户的会话内。X11 使用会话认证，关闭 TCP 监听。Chrome 以桌面用户运行，保留浏览器沙箱。Cindy 和浏览器的密钥环由每台机器独立创建。
- **账号与设备**。内测客户端在确认开通凭证、企业及成员归属后，按用户选择的可控桌面打开同账号控制和远程桌面。镜像内保持空账号和空设备状态。撤销权限通过 Cindy 设备设置生效。
- **数据与第三方应用**。浏览器原有会话、第三方账号、模型凭据、共享目录及浏览器插件授权都随实际用户和任务。遇到权限请求时走 Cindy 或对应网站的正常授权。
- **SSH**。sshd 只认 `~ubuntu/.ssh/cindy-owner-authorized-keys`，不接受密码和 root 登录。机主的设备公钥由机器上的 Cindy 写进这个文件，文件第一行带 Cindy 的标记；没有标记的文件视为手动维护，镜像不动它。`ExposeAuthInfo yes` 让每个会话带上它用的公钥，设备被撤权时 Cindy 能只断开那台设备的会话。开机时 `cindy-ssh-access-gate.service` 在 sshd 接受连接前把 Cindy 写的公钥列表暂存为 `.held`，Cindy 重新核对设备名单后写回并删除暂存；开机 10 分钟后 Cindy 仍未写回时，`cindy-ssh-access-release.timer` 恢复暂存的列表，机主仍能登录修复。两个单元都以 ubuntu 用户运行。
- **后续单独验收**。音频转发、麦克风和摄像头、中文输入法、办公套件及开发语言工具链按场景增加。桌面代理是否能读取和操作无障碍树，取决于客户端能力以及具体应用的支持，需要使用实际发布包验证。

## 构建与发布

1. CI 运行 `make test`。制镜使用干净的 Ubuntu 24.04 构建机，固定源提交和 Cindy 发行包摘要。记录架构、基础镜像版本和实装软件版本。
2. 按[构建说明](../README.zh-CN.md)在关机并单独挂载的系统盘上执行封存。用封存镜像克隆两台一次性验收机，分别检查冷启、重启、设备密钥及系统身份各自生成。浏览器试用应在克隆机进行。
3. 对每个拟开放的架构和运行形态，使用目标环境发布的客户端走下面的验收项。记录镜像仓提交、发行包摘要、Chrome 版本、云厂商镜像 ID、区域和验收结果。
4. 验收通过后，由交付服务的部署配置引用该镜像 ID。回滚时把**新订单**指回已验收的上一版镜像，同时保留版本记录。已交付实例通过用户授权的更新或重装流程升级。

## 首次开机验收

- **Host**。从购买者自己的设备列表打开新 Host，让它执行一条命令、创建并回读文件。重启后确认同一个设备身份回到在线状态，已有登录仍可用。
- **桌面**。从同账号手机或电脑连接，确认真实画面、点击、滚动、中文输入和双向文本剪贴板。打开一个 PDF、一个 ZIP 和包含中文及 emoji 的网页。重启后重复连接。
- **桌面外观**。用新建用户配置验证两种交付分辨率下的 Cindy 壁纸、深色窗口和底栏。依次打开 Cindy、Chrome、文件和终端。修改一次主题或壁纸后重启，确认能保留个人设置。
- **Chrome**。从 Cindy 或终端使用普通 HTTPS 链接打开默认浏览器，检查 Chrome 正常显示真实网页。再用 Cindy 的浏览器工具打开测试页、读取标题、填写表单和下载文件。用 Firefox 再打开同一页作为备用浏览器验收。首次运行出现的浏览器条款由用户处理。
- **Cindy 更新**。在桌面终端里取 Cindy 主进程号，运行 `pkcheck --action-id org.freedesktop.policykit.exec --process <进程号>`，应直接返回 0、不要求输入密码。确认 `~/.config/Cindy/auto-update-settings.json`（国际版为 `CindyGlobal`）内容为 `{"autoRelaunchOnIdle": true}`、权限 600。用 `journalctl -u cindy-cloud-desktop-update` 确认首次开机已检查更新：清单版本高于镜像时记录装好的版本，否则记录当前已是最新。客户端发布支持无人值守安装的版本后，再验收空闲时自动装好新版本。
- **权限与隔离**。确认购买者能操作、其他账号访问失败。撤销远程控制后复测。断开后再连接，确认服务恢复和输入状态正常。检查镜像克隆中没有构建账号、浏览器历史、已有设备身份或调试端口。
- **交付耗时**。记录从开通到设备可用、首次打开桌面和浏览器的耗时。首次可用以用户能连接、完成操作为准。

在云桌面的 XFCE 终端中可以先做系统检查，再走完整用户流程。

```sh
google-chrome --version
xdg-mime query default x-scheme-handler/https
xdpyinfo -queryExtensions | grep XTEST
gdbus call --session --dest org.a11y.Bus --object-path /org/a11y/bus --method org.a11y.Bus.GetAddress
```
